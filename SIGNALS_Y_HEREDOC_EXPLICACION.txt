# RESUMEN: SIGNALS Y HEREDOC EN MINISHELL

## 1. SEÑALES (SIGNALS)

### Conceptos Básicos
- Las señales son notificaciones asíncronas enviadas a procesos para indicar eventos
- En minishell manejamos principalmente: SIGINT (Ctrl+C) y SIGQUIT (Ctrl+\)
- Cada contexto de ejecución requiere un manejo específico de señales

### Modos de Manejo de Señales
- MODE_SHELL: Modo normal del shell interactivo
- MODE_CHILD: Modo para procesos hijos (comandos ejecutados)
- MODE_HEREDOC: Modo específico para heredoc

### Implementación en signal_handle.c
```c
// Configuración de señales según el modo
void set_signals(int mode)
{
    if (mode == MODE_SHELL)
    {
        signal(SIGINT, handle_sigint);
        signal(SIGQUIT, SIG_IGN);
    }
    else if (mode == MODE_CHILD)
    {
        signal(SIGINT, SIG_DFL);
        signal(SIGQUIT, SIG_DFL);
    }
    // Otros modos...
}
```

### Comportamiento por Contexto

#### En Shell Principal (MODE_SHELL)
- SIGINT (Ctrl+C): Interrumpe el prompt actual, muestra un nuevo prompt
- SIGQUIT (Ctrl+\): Ignorado completamente

#### En Procesos Hijos (MODE_CHILD)
- SIGINT: Comportamiento por defecto (termina el proceso)
- SIGQUIT: Comportamiento por defecto (termina el proceso con core dump)

#### En Heredoc (MODE_HEREDOC / Manejo específico)
- SIGINT: Termina el proceso de heredoc, muestra un nuevo prompt
- SIGQUIT: Ignorado

## 2. HEREDOC

### Concepto
- Redirección que permite pasar un bloque de texto como entrada estándar
- Sintaxis: `comando << DELIMITADOR`
- El texto se ingresa línea por línea hasta encontrar el delimitador

### Arquitectura
- Se implementa como un subproceso (fork) para cada heredoc
- Utiliza pipes para comunicar el texto del heredoc al comando principal
- Maneja señales de forma específica durante la lectura

### Archivos Principales

#### heredoc.c
- Función principal: `heredoc(t_command *cmd)`
- Maneja múltiples heredocs en un comando
- Crea un proceso hijo para cada heredoc
- Utiliza contexto (t_heredoc_ctx) para mantener estado

#### heredoc_utils.c
- `start_heredoc_child()`: Inicia el proceso hijo para leer el heredoc
- `handle_parent_after_child()`: Procesa el resultado del hijo en el padre
- `handle_child_status()`: Maneja diferentes casos de finalización (normal, señal, EOF)
- Manejo especial de SIGINT con `_sigint_heredoc()`

#### heredoc_utils_2.c
- `read_from_stdin()`: Lee líneas hasta encontrar delimitador o EOF
- `process_heredoc_line()`: Procesa cada línea leída
- `attach_last_heredoc_to_stdin()`: Conecta el último heredoc a STDIN

### Flujo de Ejecución

1. Se detecta un heredoc en el comando
2. Para cada heredoc:
   - Se crea un pipe
   - Se hace fork() para crear un proceso hijo
   - El hijo configura sus señales y lee de stdin
   - El hijo escribe en el pipe hasta encontrar delimitador o EOF
   - El padre espera a que el hijo termine
   - El padre maneja el resultado según cómo terminó el hijo

3. Casos especiales:
   - Si se presiona Ctrl+C (SIGINT), el heredoc termina y se cancela el comando
   - Si se presiona Ctrl+D (EOF), se muestra una advertencia pero continúa la ejecución

### Manejo de EOF (Ctrl+D)
- Cuando se detecta EOF:
  1. Se muestra: "warning: here-document delimited by end-of-file (wanted 'DELIM')"
  2. El proceso hijo sale con código 1
  3. El padre detecta este código y continúa con la ejecución

### Conexión con Pipes y Redirecciones
- El último heredoc de un comando se conecta a la entrada estándar
- Los heredocs anteriores se cierran después de procesarse
- Se integra con el sistema de pipes para comandos encadenados

## 3. INTEGRACIÓN SIGNALS-HEREDOC

### Puntos Clave
- Durante heredoc: SIGINT debe terminar la entrada y cancelar el comando
- El proceso padre debe detectar si el hijo fue terminado por una señal
- EOF debe ser manejado diferente a las señales
- Las señales deben restaurarse correctamente después del heredoc

### Consideraciones Técnicas
- Usar SIG_IGN, SIG_DFL y manejadores personalizados según el contexto
- Manejar waitpid() con EINTR para casos donde wait es interrumpido
- Cerrar descriptores de archivo correctamente en todos los casos
- Actualizar el estado de exit del shell según cómo termine el heredoc

## 4. CASOS ESPECIALES

### Heredoc Múltiples
- Se procesan en orden
- Solo el último se conecta a stdin
- Señales afectan a todos los heredocs pendientes

### Heredoc en Pipes
- El heredoc se procesa antes de ejecutar los comandos en la pipe
- Las señales durante heredoc pueden cancelar toda la línea de comandos

### Manejo de Terminal
- Se abre /dev/tty para leer directamente de la terminal
- Permite heredoc incluso cuando stdin está redirigido
