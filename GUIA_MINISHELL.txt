# MINISHELL - GUÍA COMPLETA DEL PROYECTO

## 1. VISIÓN GENERAL DEL PROYECTO

Minishell es una implementación simplificada de un shell UNIX, similar a bash, que permite ejecutar comandos, manejar redirecciones, pipes, operadores lógicos y comandos integrados (builtins).

### 1.1 Objetivos del Proyecto
- Crear un intérprete de comandos que emule las funcionalidades básicas de bash
- Implementar un sistema de parseo para interpretar la entrada del usuario
- Manejar la ejecución de comandos externos e internos (builtins)
- Gestionar redirecciones de entrada/salida y pipes
- Implementar la expansión de variables y el manejo de señales

## 2. ESTRUCTURA DEL CÓDIGO

### 2.1 Organización de Directorios
- `src/`: Contiene los archivos principales de funcionamiento
- `builts/`: Comandos integrados (builtins)
- `parse/`: Funciones de parseo de comandos
- `include/`: Archivos de cabecera (headers)
- `libft/`: Biblioteca de funciones auxiliares

### 2.2 Estructuras de Datos Principales

#### 2.2.1 t_shell
La estructura central que mantiene el estado global del shell:
```c
typedef struct s_shell_data
{
    char *line;              // Línea de comando actual
    char *prompt;            // Prompt mostrado al usuario
    t_stdfd stdfd;           // FDs estándar guardados
    char cwd[BUFFER_SIZE];   // Directorio de trabajo actual
    t_last_status last_status; // Estado de salida del último comando
    char **env;              // Variables de entorno
} t_shell;
```

- **¿Por qué es necesaria t_shell?** Actúa como un contenedor central para el estado global del programa. En lugar de usar variables globales dispersas, concentra toda la información relevante del shell en una única estructura, facilitando su paso entre funciones y manteniendo el código más organizado y modular.

#### 2.2.2 t_command_line y t_command
Representan una línea de comandos completa y cada comando individual:
```c
struct s_command_line
{
    char       *line;        // Línea completa
    char       *err_msg;     // Mensaje de error si hay
    int         n_cmds;      // Número de comandos
    bool        execute;     // Indica si debe ejecutarse
    t_command  *cmds;        // Array de comandos
};

struct s_command
{
    char            **args;          // Argumentos del comando
    char            *cmd_str;        // String del comando
    bool            builtin;         // Es un builtin?
    t_redirections  stdin;           // Redirecciones de entrada
    t_redirections  stdout;          // Redirecciones de salida
    t_redirections  stderr;          // Redirecciones de error
    t_redirections  append;          // Redirecciones de append
    t_shell         *shell;          // Referencia al shell
    t_redirections  heredoc;         // Delimitadores heredoc
    int             heredoc_fd;      // FD del heredoc
    t_command_line  *cmd_line;       // Referencia al command_line
};
```

#### 2.2.3 Estructuras para Operadores Lógicos
Para manejar operadores como `&&` y `||`:
```c
typedef struct s_cmd_parts
{
    char *cmd;       // Comando a ejecutar
    int operator;    // 0: ninguno, 1: pipe, 2: &&, 3: ||
} t_cmd_parts;
```

## 3. FLUJO DE EJECUCIÓN

### 3.1 Ciclo Principal del Shell
1. **Inicialización**: Se prepara el entorno y señales
2. **Prompt**: Se muestra el prompt y se lee la entrada
3. **Parseo**: Se analiza la línea de entrada para extraer comandos
4. **Ejecución**: Se ejecutan los comandos secuencialmente
5. **Limpieza**: Se liberan recursos y se vuelve al prompt

```
minishell() → readline() → process_input_line() → exec_line() → ...
```

### 3.2 Proceso de Parseo
1. **Lexer**: Divide la entrada en tokens
2. **Parser**: Analiza los tokens para crear estructuras de comandos
3. **Expansión**: Expande variables y caracteres especiales

```
parse_line() → get_cmds_info() → lexer() → ...
```

### 3.3 Ejecución de Comandos
1. **Verificación**: Se comprueba si el comando es válido
2. **Redirecciones**: Se configuran las redirecciones necesarias
3. **Ejecución**: Se ejecuta el comando (builtin o externo)
4. **Espera**: Se espera a que finalice y se captura su estado

```
exec_line() → process_heredoc_and_exec() → exec_last()/exec_pipe() → ...
```

## 4. CARACTERÍSTICAS PRINCIPALES

### 4.1 Parseo de Comandos
- Manejo de comillas simples y dobles
- Tokenización de la línea de entrada
- Extracción de redirecciones y argumentos

### 4.2 Redirecciones
- `>` (salida a archivo)
- `<` (entrada desde archivo)
- `>>` (append a archivo)
- `<<` (heredoc)

### 4.3 Pipes
- Comunicación entre comandos usando pipes
- Creación de procesos hijo para cada comando en la tubería

### 4.4 Builtins
- `cd`: Cambiar directorio
- `echo`: Mostrar texto
- `pwd`: Mostrar directorio actual
- `export`: Exportar variables
- `unset`: Eliminar variables
- `env`: Mostrar variables de entorno
- `exit`: Salir del shell

### 4.5 Señales
- Control-C: Interrumpir comando actual
- Control-D: Salir del shell
- Control-\: Ignorado (no genera core dump)

### 4.6 Operadores Lógicos
- `&&`: Ejecutar segundo comando si el primero tiene éxito
- `||`: Ejecutar segundo comando si el primero falla

## 7. DESAFÍOS Y SOLUCIONES

### 7.1 Expansión de Variables
- **Desafío**: Expandir variables como $USER en diferentes contextos
- **Solución**: Sistema de expansión que respeta comillas y contexto

### 7.2 Heredoc
- **Desafío**: Leer múltiples líneas hasta encontrar delimitador
- **Solución**: Uso de pipes y fork para manejar la entrada

### 7.3 Señales
- **Desafío**: Comportamiento diferente de señales en diferentes contextos
- **Solución**: Cambio dinámico de manejadores según el modo

### 7.4 Operadores Lógicos
- **Desafío**: Ejecución condicional basada en éxito/fracaso previo
- **Solución**: Nueva capa de procesamiento para líneas con operadores

## 10. CONCLUSIÓN

Minishell es un proyecto complejo que integra múltiples aspectos de la programación en C y los sistemas UNIX. Su implementación requiere un buen entendimiento de procesos, descriptores de archivo, señales y estructuras de datos.
