Minishell – Overview, syntax and behavior

1) Purpose
- A small Unix-like shell with builtins, pipelines, redirections, heredoc, variable expansion, and proper signal handling.

2) Core features
- Builtins: echo, pwd, env, exit, export, unset, cd
- External commands via execve with PATH lookup using the shell’s internal env
- Pipelines (|) and redirections (<, >, >>, 2>)
- Heredoc (<<) with correct Ctrl+C semantics (cancels, sets $?=130)
- Variable expansion: $VAR and $? (exit status)
- Readline-based prompt and history

3) Syntax quick guide
- Simple: ls -la
- Pipeline: ls -la | grep txt | wc -l
- Redirections:
  - stdin: cmd < infile
  - stdout truncate: cmd > outfile
  - stdout append: cmd >> outfile
  - stderr: cmd 2> errfile
- Heredoc (no delimiter expansion):
  cat << EOF
  line 1
  $NOT_EXPANDED
  EOF
- Variables:
  export NAME=value
  echo $NAME
  echo $?
- cd:
  cd           (goes to HOME)
  cd -         (goes to OLDPWD)
  cd ~         (goes to HOME)

4) Architecture
- shell_loop: prompt, readline, history, main loop
- parse/: lexer+parser create a command-line AST-like structure
- exec_line: runs heredocs (if any), then executes either single command or pipelines
- pipes & pipes_utils: parent/child helpers and wait/dup logic
- redirs: open/dup2 files for in/out/err and append
- heredoc & heredoc_utils: isolated child reader, parent coordination, signal policy
- expand: expands $VAR and $?
- env_utils: environment copy, free, access (get_env_value)
- fd_utils: save/restore std fds
- safe_*: thin wrappers with error messages

5) Signals
- Shell mode: SIGINT shows new prompt; SIGQUIT ignored
- Child mode: defaults (programs handle signals normally)
- Heredoc: child exits with 130 on Ctrl+C; parent cancels command and sets $?

6) Error messages
- All errors prefixed with: "minishell: ..."
- Command not found: minishell: command not found: <cmd>
- No such file: minishell: No such file or directory: <path>

7) Memory and resources
- No realloc; growth is malloc+copy
- All get_next_line buffers freed; env edits manage ownership correctly
- FDs saved/restored per command loop; heredoc closes pipe ends properly

8) Limitations / notes
- ~/<path> expansion is not implemented (only bare ~). Can be added.
- Some debug prints can be hidden behind a macro if needed.

9) Build & run
- make
- ./minishell

10) Global variables and errno
- No custom global used to receive signals. We use signal handlers and internal state.
- The global variable errno (declared by errno.h) stores error codes from failing syscalls; it’s not used as a signal receipt. Signals are handled via handlers and waitpid status.
